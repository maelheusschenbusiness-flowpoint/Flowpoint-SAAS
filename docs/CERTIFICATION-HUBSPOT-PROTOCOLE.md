# Protocole de certification HubSpot (CRM Integrations)

**État actuel : implémenté et testé localement contre une fausse API (67 tests CRM), NON certifié.** Ce protocole décrit comment obtenir la certification réelle. Rien n'est exécuté tant que les accès ci-dessous n'existent pas. Jamais de compte HubSpot client : **compte développeur / sandbox de test uniquement**. Vérifié contre le code le 17 novembre 2026.

## A. Ce qui est déjà vérifié SANS identifiants (ne pas refaire)
`services/crm/crm-hubspot.test.ts` (33), `routes/crm-readiness.test.ts` (8), `tests/crm-hub-ui.test.ts` (17) (PostgreSQL réel + fausse API HTTP locale ; rendu de l'interface en bac à sable) : chiffrement AES-256-GCM et échec fermé ; `state` haché, usage unique, expiration, cookie anti-CSRF ; jetons jamais exposés ni journalisés ; refresh, révocation (400/401/403) vs panne (429/5xx/réseau) ; `reauth_required` conservé aux appels suivants et déclenché aussi par le test de connexion ; synchronisation paginée idempotente, verrou sans course ; isolation entre organisations (contacts, journaux, mappings, leads) ; quotas par plan, transaction verrouillée ; signature de webhook v3 (secret erroné, corps altéré, horodatage périmé), déduplication, re-livraison sur 503 ; déconnexion avec révocation ; rôles owner/admin/member/viewer ; états de l'interface (non implémenté, non configuré, reconnexion requise, indisponible, add-on absent).
Pré-contrôle des prérequis (à lancer dans le shell qui porte les variables, **pas** sur le serveur) : `node scripts/certify-preflight.mjs hubspot` — vérifie 7 éléments : `HUBSPOT_CLIENT_ID`, `HUBSPOT_CLIENT_SECRET` (≥ 16 car.), `CRM_TOKEN_ENCRYPTION_KEY` (64 hex), base publique https, `FRONTEND_URL` (https, **différent de `app.flowpoint.pro`**), `CRM_WEBHOOK_PUBLIC_URL` (optionnel), absence de `HUBSPOT_AUTH_BASE`/`HUBSPOT_API_BASE`. Il refuse `NODE_ENV=production` et toute clé `*_live_`.

## C. Scénario réel (à exécuter dans l'ordre, preuves archivées)
1. **OAuth2** — organisation A (owner/admin), CRM Hub → « Connecter » sur HubSpot (ou `POST /api/crm/connect/hubspot`) → autoriser sur le compte de test. *Attendu* : retour sur `<FRONTEND_URL>/dashboard?crm_connected=hubspot` ; ligne `crm_integrations` `status='connected'`, `portal_id` = identifiant du portail HubSpot, `scope` consigné, jetons au format `v1:…` (jamais en clair) ; cookie `fp_crm_oauth` effacé. *Négatifs* : rejouer l'URL de callback → 400 ; callback sans cookie → 400 ; refuser l'autorisation → `crm_error=consent_denied` (message « Autorisation refusée »). *Rôles* : member et viewer ne voient pas « Connecter » ; leurs appels directs → 403.
2. **Test de connexion** — `POST /api/crm/test {provider:"hubspot"}` (ou bouton « Tester la connexion ») → `ok:true`.
3. **Synchronisation** — `POST /api/crm/sync` → `created` = nombre de contacts du sandbox, `truncated:false` ; relancer → `created:0`, `updated:N`, aucun doublon (`SELECT external_id, count(*) … HAVING count(*)>1` vide) ; `crm_sync_logs` : 2 lignes `success`. Comparer 5 contacts au hasard avec HubSpot (nom, e-mail, téléphone, étape). *Limite* : au-delà de 2 000 contacts, `truncated:true` (non testable avec 150 contacts : couvert par la fausse API).
4. **Renouvellement des jetons** — forcer l'expiration (`UPDATE crm_integrations SET token_expires_at = now() - interval '1 hour'` sur la base **de test**) puis resynchroniser → nouveau jeton chiffré, `last_sync_status='success'`. Constater la durée de vie réelle (`expires_in`) donnée par HubSpot et la consigner.
5. **Webhooks signés** — créer un contact dans le sandbox → HubSpot livre l'événement → ligne `crm_webhook_events`, contact présent dans `crm_contacts`. Rejouer la même livraison (re-livraison HubSpot) → `duplicates:1`, aucun second traitement. Envoyer à la main un corps non signé → 401. Vérifier que l'URL signée correspond exactement (sinon `CRM_WEBHOOK_PUBLIC_URL`). Consigner le **format réel** du corps (écarts éventuels avec `parseWebhook` : `eventId`, `objectId`, `portalId`).
6. **Isolation** — organisation B : `GET /api/crm/leads`, `/status`, `/logs` ne montrent rien de A ; `POST /api/crm/sync` → 409 `CRM_NOT_CONNECTED`. Connecter le **même** portail à B : un webhook de ce portail doit être **ignoré** (portail partagé ⇒ ambigu) ; consigner le comportement, puis déconnecter B.
7. **Quota** — *non exécutable en réel* : un seul adaptateur existe, donc aucun « second CRM » n'est connectable (couvert par test simulé avec une ligne de base). En réel, vérifier seulement que `GET /api/crm/status` renvoie `limit` = 3 (Pro) / 1 (Standard) et que reconnecter HubSpot reste autorisé (aucune place consommée).
8. **Révocation côté HubSpot** — désinstaller l'application depuis le compte de test, **forcer l'expiration du jeton d'accès** (comme à l'étape 4 : HubSpot peut laisser un jeton d'accès valide jusqu'à son expiration), puis `POST /api/crm/sync` → 409 `CRM_REAUTH_REQUIRED`, jetons effacés. Un second appel doit **rester** `CRM_REAUTH_REQUIRED` ; l'interface affiche « Reconnexion requise ». Reconnecter → `connected`. Variante : `POST /api/crm/test` avec jeton révoqué → même résultat.
9. **Déconnexion** — `POST /api/crm/disconnect/hubspot` → jeton révoqué chez HubSpot (l'application disparaît des applications connectées), jetons `NULL`, statut `disconnected` ; `GET /api/crm/leads` → `CRM_NOT_CONNECTED` ; un webhook ultérieur est ignoré. Les lignes `crm_contacts` restent en base (voir étape 10).
10. **Hygiène** — aucune valeur de jeton/secret/code dans les journaux de l'application (`grep` sur les journaux du scénario) ; supprimer `crm_contacts` de l'organisation de test (la déconnexion ne les purge pas) ; révoquer/supprimer l'application de test.
11. **Interface (captures, FR/EN/ES)** — CRM Hub dans les états : non connecté ; connecté (contacts réels) ; reconnexion requise ; HubSpot non configuré (retirer temporairement `HUBSPOT_CLIENT_ID` sur la **bêta**) ; add-on absent (organisation sans add-on) ; viewer. Vérifier que Salesforce, Pipedrive, Zoho, Monday, Airtable, Notion et Close affichent « Bientôt disponible » et jamais « Connecté ».

## D. Critères de réussite
Les 11 étapes passent avec preuves (sorties API, SQL, captures HubSpot, extraits de journaux **sans secret**), l'étape 7 étant limitée à ce qui est réellement exécutable. Une seule étape manquante = non certifié. À consigner explicitement : durée de vie réelle des jetons, limites de débit rencontrées, format réel des webhooks, comportement de HubSpot à la désinstallation.
