## Défauts (preuves)
1. **Tables absentes sur la bêta (bloquant, produit).** `organic_campaign_goals`, `technical_seo_fix_verifications` (et `seo_change_impact_settings`, `local_presence_settings`, `local_landing_opportunity_settings`, `agency_portfolio_priority_settings`) ne sont créées que dans le bloc `missing-production-tables-v3` de `init-data-tables.ts`, journalisé « already applied — skipping » sur la base de test ; le démarrage rapide ne rejoue pas `initDataTables`. Lecture `information_schema` : seules `conversion_opportunity_settings`, `gbp_performance_settings`, `google_locations`, `org_auth_config` existent. **PR de correctif isolée : #509** (base `Test-Replit`, helper idempotent + test, vérifié sur PostgreSQL jetable). Non déployée sur la bêta : tant qu'elle ne l'est pas, les contrôles 4 et 7-bêta restent à rejouer.
2. **Course à l'achat → facturation multiple (majeur, produit).** `findOrCreateAddonSubscription` (`addon-stripe-sync.ts`) cherche un abonnement d'add-on actif puis en crée un sans verrou ni clé d'idempotence : N requêtes simultanées créent N abonnements. Preuve : 3 abonnements actifs ci-dessus. Pistes : verrou consultatif par (org, add-on) autour de la synchronisation + clé d'idempotence Stripe. Non corrigé (hors « correction triviale »).
3. **Le webhook d'abonnement d'add-on écrase l'abonnement du plan (majeur, produit).** Après l'achat, `organizations.stripe_subscription_id` = l'abonnement de l'add-on (`sub_1UdH7X…`), `subscription_status` passe de `trialing` à `active` et `current_period_end` à +1 mois, alors que le plan est encore en essai jusqu'au 02/12. Conséquence directe : `syncAddonWithStripe(deactivate)` prend l'élément de l'add-on pour un élément du plan et tente de le supprimer → Stripe refuse (dernier élément) → 502 (défaut 5a). `ctx.stripeSubscriptionId` pointe sur l'abonnement de l'add-on.
4. **Réconciliation sans effet sur les add-ons à prix TEST seul (produit, mode TEST).** `persistAddonsFromSubscription` (`stripe-webhook.ts` l.501) ignore tout add-on dont `ADDON_PRICE_IDS[key]` (catalogue LIVE) est vide ; pour ces deux add-ons il vaut `""` (`plans.ts` l.361-362) : après annulation, jamais de désactivation. Piste : tester `getAddonPriceId(key)` (prix du mode actif).
5. Observation : l'e-mail d'activation n'est pas livré sur la bêta (`TEST_MAILER_NOT_ENABLED`, `RENDER` défini bloque le mailer de test).
